1. **CRITICAL — Deletion-based regeneration silently destroys facts for which the catalog is the sole authority.** The catalog exclusively owns membership, ordering, local labels, global defaults, and overrides ([doc:36](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:36)), while local labels explicitly differ from `workspace.json.name` ([doc:77](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:77)). §14 stops mirroring options into bindings ([doc:626](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:626)), yet deletion regenerates solely from current bindings and skips unreadable/dangling ones ([doc:647](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:647), [doc:659](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:659)). Consequently:

   - catalog-only option edits regenerate from stale pre-cutover binding bytes;
   - global options and inheritance choices disappear;
   - local labels and ordering are reconstructed differently;
   - configured-but-unbound entries disappear entirely;
   - missing or unreadable configured entries are omitted.

   The skip warning cannot identify unbound entries known only to the deleted catalog. The marker’s crash role is unnecessary with a correct one-file atomic write, but its provenance role—distinguishing “never generated” from “authority was deleted”—has not been replaced. Deletion must be destructive reset with explicit confirmation/backup, not ordinary absence.

2. **MAJOR — Even initial generation can flip legacy policy because “current effective values” lacks an exact normalization Interface.** §14 requires every generated entry to contain explicit effective options ([doc:661](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/docs/design/231-folder-config-authority.md:661)). Legacy `syncGit` is effectively false when omitted—the binding schema calls it default-off ([workspace-config.ts:33](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/workspace-config.ts:33)), and current consumers test `cfg.syncGit === true` ([status-projection.ts:178](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/status-projection.ts:178)). Catalog default is true ([folder-config-codec.ts:33](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/folder-config-codec.ts:33)). But the slice-1 seed permits available policy with omitted options and then emits no override ([folder-config-codec.ts:65](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/folder-config-codec.ts:65), [folder-config-codec.ts:331](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/folder-config-codec.ts:331)). That turns an omitted legacy `syncGit` from false into true. Generation needs one explicit legacy-policy snapshot function that materializes all fields, including legacy normalization/defaults; optional `options` is not a safe Interface.

   Two commands can observe absence, enumerate different `current root` unions, and overwrite each other; a generated candidate can also overwrite a hand-authored config created during enumeration. Generation must explicitly acquire the catalog lock, recheck absence immediately before publication, publish only from absence, and make losers adopt the winner. It also needs ordering for generation racing binding creation/untrack and daemon admission. The marker itself is not needed for crash safety: the current temp-fsync/rename plus directory and created-ancestor fsync gives clean absent-or-valid recovery ([folder-config.ts:285](/home/via/Development/Personal/rbox-core/.claude/worktrees/231-amendment/src/cli/folder-config.ts:285)).
