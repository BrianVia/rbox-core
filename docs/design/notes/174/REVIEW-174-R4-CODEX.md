# 174 round-4 focused index-lane amendment review (Codex)

Scope is limited to the AMENDED v5 index lane in §4.2 and the tests needed to bind that rule.

1. **HIGH — “clean against its own HEAD” does not prove that `P`'s index contains no information beyond the committed tree.** `git diff-index --cached --quiet` proves the entry content/mode projection is tree-clean, but it ignores index-only semantics. A quiet index can retain `CE_VALID`/assume-unchanged and skip-worktree bits. Sparse-checkout patterns themselves live outside the index (and outside the current remote/branch-only config lane), but their skip-worktree state and sparse-directory entries are encoded in the index and can be clean. Active merge stages 1/2/3 make the diff non-clean, so they are blocked; however, a resolved index can equal HEAD while its resolve-undo extension still retains the former conflict stages. Stat cache, cache-tree, fsmonitor/untracked-cache, index encoding, and similar performance/serialization data are safely non-semantic, but the former fields are not: design 116 explicitly includes assume-unchanged, skip-worktree, sparse-directory, and resolve-undo state in `indexIdentityV2`, and follow tests treat losing them as `local-index` data loss (`docs/design/116-checkout-follows-sync.md:328-345`, `src/engine/git/index-identity.ts:54-78`, `src/cli/sync-git/follow.test.ts:1105-1129`). Publishing `C`'s index does not preserve metadata that `C` never observed; a follower can lose sparse/status behavior or conflict-recovery state. **Minimal fix:** replace “clean” with a conservative **clean-and-plain** predicate: require exit 0 against `P`'s resolved HEAD and reject any non-stage-0 entry, intent-to-add, assume-unchanged, skip-worktree, sparse-directory semantics, or resolve-undo data. A metadata-only merge/proof could be designed later, but merely comparing metadata to `C` needs path deletion/rename semantics and is not the minimal repair.

2. **HIGH — `P.mainOid` is undefined and selects the wrong conceptual authority for multi-branch or non-main checkouts.** `GitSection` has only `head` and `refs`; its index belongs to the checkout named by `P.head`, not to a conventionally named `main` branch (`src/engine/types.ts:77-106`). **Minimal fix:** define `pendingHeadOid` after `validateGitSection(P)`: for detached HEAD it is the trimmed 40-hex `P.head`; for symbolic HEAD parse the exact `refs/heads/...` target from `P.head` and read `P.refs[target]` (validation guarantees that key is carried). Never consult live refs and never hard-code `refs/heads/main`. Peel that OID as `${pendingHeadOid}^{commit}` under `graphEnv`; missing, non-commit, or unpeelable input blocks. Use the peeled commit/tree as the `diff-index` baseline. Multiple other branches in `P.refs` are irrelevant to the index baseline.

3. **MEDIUM — fail-closed intent is correct, but artifact and exit semantics must be explicit.** A download/decrypt/hash failure, absent index lane, incomplete artifact tuple, non-regular or missing fetched file, malformed/truncated/bad-checksum index, dangling split-index dependency, unsupported required extension, or missing HEAD commit/tree/object must block. This matters because a nonexistent `GIT_INDEX_FILE` can be interpreted by Git as a new empty index rather than as corruption; on an empty-tree commit that could otherwise return clean. **Minimal fix:** require successful artifact materialization and a regular-file check before Git, then run `git diff-index --cached --quiet <peeled-pending-head> --` with the absolute `GIT_INDEX_FILE` plus `graphEnv`. Exit 0 alone passes; exit 1 is dirty and blocks; every other nonzero status or thrown error also blocks. Preserve §4.2's existing “absent lane fails closed” rule. The current equality implementation's `null === null` path (`src/cli/sync-git/pending-supersession.ts:101-119,165-169`) must not survive the amendment.

4. **HIGH — the suite plan only partially covers the amended rule.** The live rig's X2→Y content commit makes the two clean indexes unequal and its maiden failure therefore exercises the positive case, but §5.1 says only “ahead ≥1 commit” and never asserts unequal `indexIdentityV2`; that fixture could regress to an empty/tree-identical commit without testing v5. Section 5 has no dirty-pending-index supersession negative at all; test 3 is apply-side skip behavior, and test 5 does not use real index artifacts (`docs/design/174-apply-side-perf-and-held-repo-livelock.md:450-475`, `src/cli/sync-git/pending-supersession.test.ts:38-83`). **Minimal fix:** add real-artifact unit cases in which (a) `P` is clean at commit A, `C` is clean at fast-forward B, their `indexIdentityV2` values are asserted unequal, and supersession succeeds; and (b) `P` contains staged work relative to A and supersession blocks. Bind finding 1 with clean assume-unchanged/skip-worktree/sparse/resolve-undo negatives, and bind findings 2-3 with non-main symbolic, detached, missing, and corrupt-artifact cases. Also state the unequal-index assertion in §5.1 so the rig remains a direct v5 regression.
