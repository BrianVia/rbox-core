# Design 163 adversarial review — round 1

## Verdict: CHANGES-REQUIRED

SQLite is the right class of primitive for row-local persistence and concurrent reads, but this draft does not yet specify a safe reset protocol, an implementable bounded-memory engine port, or a crash-resumable migration/downgrade protocol. The central safety claim — that transactions replace the file-swap mechanics beneath design 138's unchanged contracts — is not true across the journal, marker, Git refs, archive/quarantine artifacts, and database. Several performance premises also overstate what the code does today and what the store swap alone removes.

## Field-claim audit

| Symptom family | Result |
|---|---|
| 1. Reset admission | Verified, with one wording correction: current admission is exactly 26×2=52x, 512 MiB hard materialization cap, machine-scaled 4 GiB floor / 32 GiB ceiling with lower cgroup hard limit winning. |
| 2. Interactive status | The 12.2 s fallback parses full state BUT then performs a complete scan, full diff, and Git divergence evaluation. SQLite removes only the baseline-parse component. |
| 3. Daemon memory | Code proves repeated full-state parsing and large transient maps/copies, but not that every cycle serializes or that JSON alone caused the entire RSS slope. |
| 4. Cycle I/O | The universal no-op rewrite claim is false in code (true no-ops skip state-save; the observed saves were the undefined-vs-{} guard bug, since fixed in #349). |

## Findings

1. **CRITICAL — The design does not contain design 138's required normative crash-window re-derivation, and a SQLite transaction cannot cover the existing multi-resource protocol.** 138's durable boundaries are not all state-file writes: journal phases (reset-journal.ts:377-386), recovery refs one at a time (:389-398), active state install + two parent syncs (:465-479), external incarnation marker (:484-490), Git-ref group retirement (:401-420,491-499), journal unlink/fsync (:501-509). A DB transaction can collapse only the active-state mutation. The P*/R*/I*/Z0 rows cannot remain unchanged: if reset is an in-place SQL transaction there is no rename candidate (R2); if it still builds and renames a candidate database, WAL is not replacing the file swap. Choose ONE mechanism and include a new normative table enumerating prepared+old DB, ready+old DB, ready+new DB after commit/before installed, marker old/absent/new, every recovery-ref prefix, every active-ref-group prefix, archive publication, terminal journal removal. Every unlisted correlated signature must still halt with zero writes.

2. **CRITICAL — integrity_check is not an exact-old/exact-new state witness, and the proposed Bun backup mechanism does not exist as stated.** 138 admits active state only when byte-hash-exact old or canonical new (138:139-163). SQLite integrity_check validates B-tree consistency; a well-formed database with one altered sha/mode/repo/sequence passes it. A physical hash of state.db is unusable while WAL/checkpoint state varies. Needs a canonical logical digest transactionally bound to stream/nonce/revision, OR an architecture where the at-rest file hash remains valid. Separately: Bun 1.3.14 exposes Database.serialize() (sqlite3_serialize, O(size) in-memory buffer — unacceptable at 512 MiB), not sqlite3_backup. Choose an available primitive (C online-backup API or VACUUM INTO) and specify staging, snapshot semantics, verification, fsync, atomic publication, crash cleanup.

3. **CRITICAL — The promised cursor/iterator memory model is not an implementable port of the actual engine topology.** All relevant APIs require whole Manifest objects: scan accumulates+sorts+returns full manifests (manifest.ts:98-133,151-199; watcher hot path indexes the entire old manifest :256-377); pull retains base+local+remote, reconcile builds three full maps + union + action array (pull.ts:76-93,114-132,165-209; reconcile.ts:41-76); push retains local+applied base, path sets, two-map diffs (push.ts:328-375; sync-recovery.ts:130-175,524-537); the daemon retains manifest + syncBase, re-materializes scans, allocates full diff maps for ambient (daemon.ts:273-280,721-725,1569-1581,1908-1938); wire commit walks the whole manifest, snapshot encoding JSON.stringify, delta encoding builds two maps + full ops array (e2ee-remote.ts:668-795; manifest-delta.ts:277-295,324-349) and wire changes are a non-goal. A safe bounded-memory design needs an ordered merge architecture: scan-generation/temp table, generation visibility, base/local/remote merge, ignore deferral + mass-delete counts, action streaming without violating the pre-apply decision barrier, and explicit unavoidable wire materializations. Until peak live objects and materialization boundaries are specified and measured, the multi-GB claim is unsupported.

4. **CRITICAL — The one-way import has no crash/disk-full state machine; database presence is not an authority predicate.** SQLite creates state.db and possibly -wal/-shm before an import transaction commits; crash or SQLITE_FULL leaves a present-but-partial database and the import trigger no longer matches. Crash after commit but before JSON rename leaves both representations with no resume rule. Require a migration state machine with a completion record inside the same transaction as imported data, validated application/schema IDs on every open, explicit branches for absent/partial/complete DB × absent/active/backup JSON; staging sibling build + close/checkpoint/verify + fsync file and directories + atomic publish + fsync parent; JSON rename as a separately durable resumable finalize. Note writeFileAtomic does not sync the parent (fsutil.ts:10-14,34-68); 138's helpers add that explicitly (reset-journal.ts:226-234).

5. **CRITICAL — The downgrade story is contradicted by old-binary code and creates a split brain outside 138 consent.** loadRawState synthesizes an empty sequence-zero state from state-incarnation.json when active JSON is absent; loadState accepts it when the stream matches (config.ts:384-400,725-765) — no StreamMismatchError, no consent witness. Old binaries recreate and advance state.json while new binaries prefer the DB — silent history fork. The bake release needs a durable "SQLite-authoritative" marker old binaries hard-error on, or a supported fenced export/downgrade transaction. A stale pre-migration backup is not a downgrade protocol.

6. **HIGH — 512 MiB and ENOSPC cases are not operationally recoverable under default-on migration.** Exactly-512-MiB needs 26 GiB parse headroom; migration free-space demand can include JSON+DB+WAL+archive simultaneously. Specify advisory preflight + authoritative SQLITE_FULL handling, JSON stays authoritative on every pre-commit failure, positively-identified staging cleanup only, legacy-engine continuation or a typed non-looping migration-halt with doctor output. Fault-inject every boundary including near-512MiB and guard-refused states.

7. **HIGH — 'verify row counts + lineage' cannot establish lossless migration; the schema sketch does not map the current state contract.** SyncState includes manifest metadata, removal/resolution maps, pending remote sections, legacy deferrals/partials, telemetry identity, generation-CAS RepoRecords (config.ts:132-200). Counts+lineage cannot detect wrong hash/mode/mtime, dropped optional maps, lossy encoders. files(path PK,...) fails to say whether it stores synced base, daemon-local truth, or both — three-way reconcile needs a plane/generation key. Freeze a field-complete logical schema with every FileEntry/GlobalManifestMeta/RepoRecord field and CAS semantics; prove canonical digest equality or a full streaming semantic round trip before moving JSON.

8. **HIGH — WAL alone does not match 138's durability guarantees.** Pin and VERIFY journal_mode=WAL and synchronous=FULL (NORMAL can roll back committed transactions on power loss); define checkpoint/truncation and -wal/-shm handling; fsync new directory entries; the enable-WAL result must be checked. Ordinary saves omit parent-dir fsync today (fsutil), but 138 reset/quarantine requires stronger boundaries (138:189-203,390-420) that WAL does not cover for DB creation, backups, sidecars, markers, journals. Process-kill + power-cut/filesystem fault tests at the new normative boundaries.

9. **HIGH — PRAGMA integrity_check on open contradicts the fast read path.** Full check is O(N log N), quick_check O(N), synchronous in Bun — not a microsecond SELECT, blocks the CLI event loop, retains read snapshots delaying checkpoints, and still isn't a semantic witness. Use cheap per-open checks (application ID, schema/user version, required meta, migration-complete, lineage); schedule full checks on doctor/migration/suspected corruption/bounded cadence with an explicit corruption-state transition.

10. **HIGH — The cold/unsettled status acceptance story attributes scan work to the state store.** Status always loads state first, then (untrusted) builds ignore matcher, scans the tree, materializes path sets, diffs two manifests, waits for Git divergence (status-cmd.ts:365-388,409-430,468-499; diff.ts:39-54). SQL cannot know current disk changes; the read-only CLI connection cannot use a persistent scan-generation table as drafted. Revise the claim to the parse component, or specify a different status architecture. The <200 ms target does not validate the 12.2 s unsettled fallback.

11. **MEDIUM — Git planning needs defined store APIs and CAS semantics.** planGitSections takes complete SyncState, clones maps, expands records (plan.ts:98-147); repoRecordsForState reconstructs every map (config.ts:408-455); applyStateSavePacket provides whole-packet stream/nonce/global-seq checks + per-repo generation CAS (config.ts:513-599). Define lineage snapshot, ordered repo cursor, per-repo generation read, atomic multi-repo/global CAS packet; state which Git stages use individual lookups vs when the complete wire gitRepos map is intentionally materialized.

12. **LOW — Crypto-worker thread topology is currently safe; make the ownership invariant normative.** Workers are separate isolates, no state/DB in messages. State explicitly: every Database is created, used, closed in its owning isolate, never posted to workers.

13. **LOW — 'Layer B was never built' is imprecise.** The daemon already owns and incrementally patches an in-memory manifest (daemon.ts:263-280,1237-1263); the unbuilt Layer B was CLI-to-daemon delegation (85:344-352).

## Required revision before round 2
1. Complete replacement for 138's normative correlated row table and an exact logical old/new state witness.
2. An available bounded backup/snapshot primitive with all durability boundaries.
3. Explicit base/local/remote data model and ordered scan/reconcile/apply/push APIs, with peak-materialization budgets and unavoidable wire materializations called out.
4. Resumable import authority state machine, ENOSPC cleanup/fallback, semantic verification, real downgrade/old-binary barrier.
5. Pinned WAL/FULL/checkpoint settings, integrity checks off every open, corrected status/no-op/RSS claims.
