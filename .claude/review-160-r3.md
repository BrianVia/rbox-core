# Design 160 adversarial review — round 3

**Verdict: CHANGES-REQUIRED**

v3 closes the substantive round-2 gaps: the inverse outcome is real, per-choice copy is the right fallback when it occurs, the budget must enter matcher preparation, rendered inventory counts must be separate from internal work units, and the direct-init root expression now matches the planner at `src/cli/init-plan.ts:168-170`. The remaining findings are narrower contract edges and editorial/test completeness issues.

1. **HIGH — The descending preview walker still lacks the per-policy ancestor-prune contract required for scanner parity.**

   Evidence: the design says the dedicated walker physically descends into skipped directories and that “only the per-path DECISION comes from the shared resolver” (`docs/design/160-gitignore-sync-preview.md:93-98`). Production inclusion is not a leaf-only `matcher.ignores(path)` decision: `scanManifest` first calls `matcher.prunes(dir)` and never visits that directory's descendants after a true verdict; only descendants of reached directories receive file/symlink `ignores()` calls (`src/engine/manifest.ts:572-605`). The distinction is especially material to B′: `ignores()` applies tracked protection only to non-directories (`src/engine/ignore.ts:426-437`), while `prunes()` can keep a root-ignored directory open because it may contain tracked descendants (`src/engine/ignore.ts:440-452`). A top-level directory can therefore contain a mix of skipped and synced descendants under one policy; classifying or grouping it from the directory's `ignores()` result is wrong. Continuing to call the matcher below a production-pruned ancestor can also lazily consult descendant `.gitignore` files through `getGitLayer`/`nestedGitDecision` (`src/engine/ignore.ts:297-305,321-339`), contradicting the promised “effective” count that excludes rule files beneath pruned parents (`docs/design/160-gitignore-sync-preview.md:117-122`). The file/symlink parity oracle does not by itself specify how the preview must avoid those consultations or form honest mixed-directory groups.

   Required change: specify that physical traversal carries an independent ancestor-pruned state for each policy. Once that policy's `prunes(dir)` is true, all syncable descendants are classified skipped for that policy without consulting descendant rule files for that policy; physical descent continues only for bounded inventory/group estimates. When `prunes()` is false but `ignores(dir)` is true, classify descendants individually rather than labeling the whole group skipped. Make the existing pruned-directory/effective-rule fixture assert this behavior and the per-choice group counts.

2. **MEDIUM — Define the four sets extensionally; the current source labels are not exhaustive partitions.**

   Evidence: the authoritative partition is the pair of final resolver results, not the rule source. For `(respectGitignore: true, respectGitignore: false)`, A is `(skip, skip)`, B is `(skip, sync)`, B′ is `(sync, skip)`, and C is `(sync, sync)`. The causal descriptions at design lines 67-72 are only typical cases. Root `.rboxignore` rules are appended after builtin/root-gitignore rules (`src/engine/ignore.ts:281-288`): a negation can rescue a root-ignored path into C, while a positive `.rboxignore` match can keep a tracked root-ignored path in A (`src/engine/ignore.ts:342-370,413-437`). B′ is also not limited to proven tracked regular files. Tracked protection applies to any non-directory path, including Git-tracked symlinks (`src/engine/ignore.ts:384-394,426-437`; symlinks use the same resolver in `src/engine/manifest.ts:586-603`), and an unavailable tracked set is deliberately treated as “possibly tracked” (`src/engine/ignore.ts:391`), so a root-ignored path can enter B′ without proven trackedness.

   Required change: make the boolean truth table the definitions of A/B/B′/C and label the listed rules as common causes. Describe B′ as root-gitignored syncable entries that the resolver protects as tracked or possibly tracked, including symlinks. Add at least a tracked-symlink or unavailable-index inverse case. Also correct the founder-warning claim that root-ignored files are “never” synced under option 2: `.rboxignore` can re-include one under either policy.

3. **MEDIUM — The budgeted matcher's incomplete-result and two-policy composition contracts are still unspecified.**

   Evidence: v3 says `buildIgnoreMatcher(root, { readOnly: true, budget })` returns an explicit incomplete result when preparation caps (`docs/design/160-gitignore-sync-preview.md:100-110`), but the current public API returns `IgnoreMatcher` directly and its callers immediately consume matcher methods (`src/engine/ignore.ts:279,473-480`). The preview needs corresponding matchers for both policy values, yet the design shows one construction and does not say how two builds share the same budget or how completion is combined. A global union return would unnecessarily break the many existing unbudgeted call sites; exposing the first matcher before the second completes would violate the stated no-partial-decisions rule.

   Required change: name a discriminated result shape or overload that preserves the existing unbudgeted return contract, for example `{ complete: true, matcher } | { complete: false, reason }` only for budgeted construction. State that both policy matchers consume the same budget and the preview exposes neither unless both are complete.

4. **LOW — The cap tests omit the second matcher-preparation boundary, and the option-label prose contradicts v3's own model.**

   Evidence: preparation now includes both streaming repository discovery and per-repository trackedness loads (`docs/design/160-gitignore-sync-preview.md:100-105`), but the required boundary tests name only “mid-discovery and mid-walk” (`:113-115`). A trackedness load performs `rev-parse`, stat/cache access, and possibly `ls-files` (`src/engine/ignore.ts:593-609`), so fail-closed behavior between repository loads is not covered. Separately, the founder section still says the flag “ONLY toggles” nested `.gitignore` honoring (`docs/design/160-gitignore-sync-preview.md:17-27`), which B′ itself disproves, and the design says it assumes relabeling while also saying the choices stay “exactly as-is” and showing the old label (`:31-37`).

   Required change: add a multi-repository cap/deadline test that stops between tracked-set loads and asserts the same incomplete abort with no rendered decisions. Rewrite the policy prose to acknowledge the root trackedness inverse, and distinguish unchanged values/defaults from the still-pending label text.

Targeted baseline verification: `bun test src/engine/ignore.test.ts src/cli/init-plan.test.ts` completed with **47 pass, 0 fail**. This confirms the cited current resolver/planner behavior; it does not exercise the proposed preview contracts.
