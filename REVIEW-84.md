## Round 1 — codex (sol)

1. **BLOCKER — The advertised broken-chain recovery cannot pass the landed head-authority gates, so one bad delta can permanently wedge every current writer.** Design 84 says a device with an intact local folded base can react to a chain-integrity pull failure by emitting a fresh snapshot on its next push (`docs/design/84-manifest-delta-encoding.md:351-368`). Current `verifiedHead()` advances the anti-rollback pin only after verifying the signed chain and terminal head, but *before* manifest decode/apply (`src/cli/e2ee-remote.ts:227-258`; decode happens later at `src/cli/e2ee-remote.ts:178-183`). If delta folding then fails, `lastSyncedSequence` remains the older applied sequence. The next commit is explicitly rejected when pin sequence != applied `parentSequence` (`src/cli/e2ee-remote.ts:411-420`), and the normal conflict loop pulls before retry (`src/cli/sync.ts:489-493`), which fails on the same broken chain. `rbox recover` does not provide the claimed escape hatch: it clears the pin and immediately pulls the server head (`src/cli/recover-cmd.ts:53-77`), so it also must decode the broken head. Specify an explicit, authenticated repair transaction that can sign a snapshot as a child of the DO-authoritative head without first applying that head (including how it obtains/verifies the parent hash, how local applied state is selected, how destructive stale-state publication is guarded, and what `recover` does). The current “automatic next push” text is impossible post-design-91/92.

2. **BLOCKER — `manifestChain` cannot establish I3 as specified: the zero-knowledge server can validate addresses, but cannot validate that the signed list is complete or corresponds to the encrypted delta chain.** I3 promises every link is GC-rooted (`docs/design/84-manifest-delta-encoding.md:106-111`), while §3.5 only shape/presence-checks a client-supplied list (`docs/design/84-manifest-delta-encoding.md:292-330`). Because the actual `baseEncSha` links remain encrypted, a buggy or hostile writer can omit a required base from `manifestChain`; the commit is accepted, later GC sees no root, and the live head becomes unreadable. Current GC is deliberately fail-closed only over what the DO can enumerate: `roots()` parses signed bodies and emits `encManifestSha` plus data refs (`apps/api/src/workspace-sync.ts:474-514`), and Phase 1 treats precisely that union as authoritative (`apps/api/src/gc-phase1.ts:28-42`). The protocol must require readers/writers to compare the decrypted chain exactly against the signed `manifestChain` (order, terminal snapshot, every immediate `baseEncSha`, no extras), define the failure before pin advancement, and accurately downgrade server enforcement to syntactic/presence enforcement. If buggy signed writers are in scope for I3, a server-visible parent-link field (or another enforceable construction) is required; the present design cannot make its stated invariant true.

3. **BLOCKER — The envelope wire format and compatibility discriminator are not implementation-ready.** The design calls the plaintext “self-describing” but gives no envelope version/magic, no strict allowed-field schema, and no normative legacy-reader rule (`docs/design/84-manifest-delta-encoding.md:95-100,133-160`). Phase B says readers support raw legacy manifests plus envelopes (`docs/design/84-manifest-delta-encoding.md:493-505`), yet does not say whether any object with `kind` is an envelope, how a legacy manifest containing an unknown `kind` property is treated, or how unknown future envelope versions fail. The compressed snapshot example places a “zstd payload” in a JSON `manifest` field without defining its JSON representation, uncompressed-length cap, compression-bomb limit, or whether `manifestHash` covers decoded JCS or original serialized bytes (`docs/design/84-manifest-delta-encoding.md:140-160`). Current encrypted blobs are exact opaque bytes (`src/engine/e2ee/manifest-crypto.ts:32-47`), and current decode is unambiguously raw JSON -> `Manifest` (`src/cli/e2ee-remote.ts:205-215`). Choose a versioned type (for example an unambiguous `type: rbox/manifest-envelope/v1`), fully specify raw-v0 discrimination and strict parsing, and define the compressed byte encoding and bounds before dispatch.

4. **MAJOR — The re-baseline section silently weakens design-91 continuity and is not reconciled with either current code or `rbox recover`.** Design 84 proposes accepting a merely signature-valid newer head while skipping unverifiable ancestry and says this is “exactly what [re-baseline] gives up today” (`docs/design/84-manifest-delta-encoding.md:397-423`). That is not current reality: `verifiedHead()` always calls `commitsSince(pinnedSeq)` and verifies the full forward chain to the exact `/latest` terminal hash (`src/cli/e2ee-remote.ts:227-258`); a `NeedsRebaselineError` is not caught there. The only catch is the retained-history helper, which searches for a segment still anchored at the already verified head (`src/cli/e2ee-remote.ts:345-389`). Meanwhile `rbox recover` is an explicit user-confirmed pin reset with a sequence-floor precheck (`src/cli/recover-cmd.ts:39-67`), not an automatic pull behavior. Decide whether automatic continuity-skipping is actually intended and obtain design-91-level threat-model agreement; otherwise make re-baseline an explicit recovery ceremony. Also specify equal-sequence/same-hash behavior, roster-at-commit verification, pin-write ordering, and how a pruned `commitsSince(0)` after `recover` is avoided.

5. **MAJOR — The client-state plan predates design 93's generation-CAS state writer and would permit torn or stale delta-base metadata if implemented as “three optional fields at save sites.”** The design treats `SyncState` and existing saves as direct field updates (`docs/design/84-manifest-delta-encoding.md:231-264`). Current state publication is a whole `StateSavePacket` guarded by stream, incarnation nonce, global sequence, per-repo generations, and lock ownership (`src/cli/config.ts:159-171,301-348`). Pull advances the global base only after filesystem and git application, and push publishes it via `saveStateSource` (`src/cli/sync.ts:343-346,705-725`). The manifest address/hash/chain-position tuple is correctness-critical and must be part of the same `packet.global` CAS unit as `sourceGlobalSeq` and `globalManifest`; it must never update on verify-only/pin advancement, partial apply, rejected packet, repo-pending projection, or mutex-degraded fallback. Revise the state schema and packet/application semantics explicitly, including migration and stream-reset behavior. This is also the mechanism that must preserve design 92's applied-base rule: push decisions use only `lastSyncedSequence`/`lastSyncedManifest`, never a verified-but-unapplied head (`src/cli/sync.ts:530-536`).

6. **MAJOR — The GC/accounting integration is stale after designs 95 and 24 and is not a “one-line union.”** The design cites old handler lines, says chain refs get “the same treatment, minus charging,” and describes clearing a prune marker (`docs/design/84-manifest-delta-encoding.md:304-335`). Current commit publication has inline-vs-sidecar carriers, receipt redemption, a `MAX_REFS_PER_COMMIT` accounting budget, and builds `shas` differently for each mode (`apps/api/src/workspace-sync.ts:263-341`). `CommitBodyView` and the signed engine `CommitBody` do not contain `manifestChain` (`apps/api/src/commit-envelope.ts:84-94`; `src/engine/e2ee/commit.ts:33-56`), and `roots()` has bounded retained-sequence/total-ref accounting plus sidecar fetch failure semantics (`apps/api/src/workspace-sync.ts:474-514`). More importantly post-95, `commitAccounting` can have the *whole super-batch* trigger-aborted by an R2 delete fence and returns all refs as `needsUpload` (`apps/api/src/commit-accounting.ts:185-193`); receipt minting itself fails closed while a delete fence is open (`apps/api/src/blobs.ts:49-78`). Specify whether chain links join accounting `shas` (and carrier/ref-count budgets), how already-entitled-but-Phase-1-marked links re-grant and clear `blob_ref_candidates` (`apps/api/src/commit-accounting.ts:169-182`), how a design-95 fence abort maps to retry without attempting to re-upload immutable historical links, and how `ROOTS_MAX_TOTAL_REFS` counts chain entries. Add the chain to the engine signer/parser, Worker parser, DO roots DTO, `versions.ts` reachable union, and all fail-closed tests; otherwise links can be omitted at one of several authoritative seams.

7. **MAJOR — Delta application does not explicitly preserve design 92's manifest-entry integrity and fail-closed carry contract.** Saying a `set` entry is “self-validating via `validateManifest`” (`docs/design/84-manifest-delta-encoding.md:162-190`) covers shape only. Current validation checks paths, tuple shapes, compression descriptors, collisions, and git sections (`src/engine/manifest-validate.ts:49-153`), while the landed producer path separately authenticates scanned `(sha256,size)` against encrypted bytes and defers churn rather than mutating the tuple (`src/cli/sync-recovery.ts:223-246,275-312`); push then builds the committed stable subset from the *applied* base (`src/cli/sync.ts:639-645`). The delta writer must diff the final `committed` manifest after deferral/schema stamping, not a scan/change stream, and the fast fold must not mutate the cached applied base before `resultHash`, full `validateManifest`, and filesystem apply succeed. Require tests for poisoned `set` tuples, compressed descriptor changes, deferred carry, verified-but-unapplied heads, and retry after apply-integrity failure—not only randomized structural fold equality.

8. **MAJOR — Phase 0 is already implemented and its proposed schema is stale, so the rollout cannot begin as written.** Current pull records `latest` details (`src/cli/sync.ts:218-227`) and current commit records details (`src/cli/sync.ts:673-682`) through the exact `recordDetails` channel (`src/engine/phase-report.ts:165-172`). The shipped commit timing is broader than design 84's `{encodeMs, encryptMs, uploadMs, encBytes}`: it includes account refresh, refset sidecar upload, and commit POST (`src/cli/e2ee-remote.ts:392-502`; formatter at `src/cli/sync.ts:93-95`). Therefore Phase A is measurement/analysis, not an instrumentation implementation phase, and “commit = encode + encrypt + upload” no longer closes the timer. Revise the decision arithmetic to include `refreshMs + sidecarMs + postMs` (and quantify residual/unattributed time), record current two-host v1.0.0+ measurements, and make the C1/C2 gate decision from those shipped fields. `src/cli/metrics.ts` only enables/constructs the report (`src/cli/metrics.ts:17-28`); the detailed data is emitted by `sync.ts`, which the design should cite.

9. **MINOR — Several mechanism/line claims have drifted enough to misdirect implementation.** Examples: manifest encode/upload is now `src/cli/e2ee-remote.ts:453-485`, decode is `:191-215`, the server conflict is `apps/api/src/workspace-sync.ts:343-390`, roots are `:474-514`, state fields are `src/cli/config.ts:94-129`, scan stamping is `src/engine/manifest.ts:91,198`, and the pack byte-bound helper is `src/cli/sync-git.ts:243-244` rather than the cited locations. Refresh every citation as requested, and update claims that `commitsSince` is “untouched”: adding `manifestChain` changes the signed commit body/types and every parser even if chain verification remains opaque. `docs/design/96-roots-index.md` is absent on this branch, so no design-96-specific constraint was reviewed; current design-95/current-main GC behavior is covered above.

10. **MINOR — Chain sizing and historical decode leave implementer choices that affect correctness and cost.** `MAX_MANIFEST_DELTA_CHAIN` remains an open decision despite being a wire/server acceptance limit (`docs/design/84-manifest-delta-encoding.md:217-225`); define whether the count includes head and snapshot and whether `manifestChain` includes the current `encManifestSha` (the prose currently says snapshot + intermediates, while I3 says every link). Define “bytes” as ciphertext bytes and how readers obtain trusted sizes. Also specify the primitive used to decrypt base links: current `openCommitHistorical` authenticates bytes against one commit's signed `encManifestSha` (`src/engine/e2ee/session.ts:376-399`), so it cannot be reused with the head commit for arbitrary base blobs. A chain decoder needs a bounded address-authenticated decrypt path using the signed `manifestChain`, with epoch selection and errors defined, and history/path-history should share folds rather than independently refetching the same chains.

**Final verdict: REVISE.** The core O(change) direction and the requirement to root every delta link are sound, but the design is not implementation-ready against current main. The head-authority repair deadlock, unenforceable completeness claim, and underspecified versioned wire format are blockers; the landed state-CAS, integrity, receipt-fence, roots-bounds, and already-shipped instrumentation paths require substantive revision before implementation dispatch.
