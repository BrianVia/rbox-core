## Deliverable 1 — Round 1 — codex

- **HIGH — P-1 violation: an `unlinkDir` subtree rescan can publish an unstable child as a deletion.** `applyWatchEvents` calls the now-deferring `walk` without a `deferred` set when re-deriving a still-present directory (`src/engine/manifest.ts:151`). If a child changes between stat and hash, `drainHashes` silently omits it because no set was supplied (`src/engine/manifest.ts:369-373`); the authoritative-fresh-set cleanup then deletes the child's prior coherent entry (`src/engine/manifest.ts:153-157`). A stale `unlinkDir` event followed by a daemon push can therefore turn append/replace/chmod churn into a remote deletion. Thread a deferred set through this subtree walk, preserve prior entries for deferred children, and schedule the existing retry path. Add a deterministic daemon/incremental regression covering this exact ordering.

- **HIGH — P-1 violation: post-pull scan deferral can clobber the version just pulled.** After `pull()` applies remote content and advances the persisted sync base, `doPull` calls `replaceManifestFromScan(this.cache, this.manifest)` with the pre-pull in-memory manifest as the carry source (`src/cli/daemon.ts:794`; helper at `src/cli/daemon.ts:1162-1166`). If a remotely changed path is unstable during that rescan, the helper restores its stale pre-pull entry (or pre-pull absence). The pump's follow-up push can then interpret that stale tuple/deletion as a local change against the new base and overwrite the remote version before the 200 ms retry runs. This site must carry from coherent post-pull truth (for example the newly loaded `lastSyncedManifest`) or suppress pushing until re-derivation succeeds. Add a deterministic post-pull defer-then-push regression.

- **MEDIUM — HashCache v2 accepts corrupt entries inside an otherwise valid envelope.** `HashCache.load` validates `{version: 2, entries: object}` but does not validate each entry (`src/engine/hashcache.ts:82-90`). A syntactically valid damaged entry with matching numeric `(mtimeMs,size,ctimeMs)` and an arbitrary/malformed `sha256` is accepted by `lookup` (`src/engine/hashcache.ts:41-44`). Since the cache is specified as safe-to-discard and corruption must cost only a re-hash, validate v2 entries (including finite fingerprint fields and a valid SHA-256) and discard the cache wholesale on any malformed entry. The current corruption test covers invalid JSON only.

- **LOW — the restored-mtime stale-SHA gate does not assert its ctime premise.** The test proves equal size/mtime and verifies the new SHA (`src/engine/engine-m1.test.ts:183-205`), but never asserts `st2.ctimeMs !== st1.ctimeMs`. On a filesystem with coarse or surprising ctime behavior this can fail nondeterministically without identifying why. Assert the ctime change (or use a deterministic stat seam) so the test explicitly gates the P-2 fingerprint dimension it names.

- **PASS — required direct gates and ordinary production call sites.** The append, same-size atomic replacement with restored mtime, and chmod-at-hash full-scan cases deterministically defer and emit no mixed tuple; the shared predicate covers file type, ino, dev, size, mtime, ctime, and mode; the foreground push test carries the base entry; same-size write plus restored mtime re-hashes; legacy bare-map cache data is discarded and rewritten as v2. Both direct `HashCache.lookup` and `record` production call sites pass ctime/post-stat values, and the foreground push plus retry rescans thread scan deferrals. Targeted tests passed (35/35) and typecheck passed. The full `bun test ./src/` run encountered unrelated failures in `git-state.test.ts` and the documented `sync.test.ts` metadata-heal case before it was stopped.

Verdict: REVISE

## Deliverable 1 — Round 1 — revision (Claude)

All four findings accepted; dispositions:

1. **HIGH (unlinkDir subtree rescan deletes an unstable child) — ACCEPTED.** `applyWatchEvents`' still-a-dir `unlinkDir` branch now walks with its own deferred set: a child absent from the fresh walk because it was DEFERRED keeps its prior entry (excluded from the authoritative-subtree cleanup) and is surfaced to the caller's deferred set for the existing write-finish retry. The `addDir` branch threads the caller's deferred set through its subtree walk too. Regression: stale `unlinkDir` + churn-at-hash on the child → prior entry retained + path deferred (fails on the pre-fix code, verified by stash).
2. **HIGH (post-pull carry source is pre-pull truth) — ACCEPTED.** `doPull` now carries deferred paths from the freshly loaded POST-pull `lastSyncedManifest` (one `loadSyncBase` call also feeds `lastLoggedSeq`), never the pre-pull in-memory manifest. Regression (daemon-scan-defer.test.ts) uses the sharp variant — a freshly PULLED file deferred during the post-pull rescan: carried-from-pre-pull it is ABSENT and the chained push commits its deletion with no blob upload to catch it (the modified-file variant is masked by upload-time churn deferral). Fails without the fix (head advances to 3, g.txt deleted), passes with it (verified by stash both ways).
3. **MEDIUM (v2 envelope accepts corrupt entries) — ACCEPTED.** `HashCache.load` validates every entry (finite mtimeMs/size/ctimeMs, 64-hex sha256); ANY malformed entry discards the whole file — wholesale by contract, a damaged sha must never flow into a manifest. Test covers bad sha, wrong type, legacy shape inside a v2 envelope, and null.
4. **LOW (touch-r gate does not assert its ctime premise) — ACCEPTED.** The test now asserts `st2.ctimeMs !== st1.ctimeMs` alongside the restored-mtime/size equalities, so a coarse-ctime filesystem fails identifiably at the premise.
